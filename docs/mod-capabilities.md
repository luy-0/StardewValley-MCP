# Mod 能力一览

本文面向安装者、MCP 客户端开发者和 Agent 作者，说明当前 Stardew Valley MCP Mod 已实现的全部公开能力。当前 V1 共注册 **20 项能力**：5 项只读观察能力和 15 项游戏操作能力。

本文是便于阅读的使用说明，不重新定义协议。能力集合与策略以 [`../spec/capabilities/manifest.yaml`](../spec/capabilities/manifest.yaml) 为准，字段以 [`../spec/proto/`](../spec/proto/) 为准，详细行为边界以 [`../spec/capabilities/behavior.md`](../spec/capabilities/behavior.md) 为准。

## 能力如何对外出现

Mod 会在启动和握手时公告自己实际注册的能力。MCP 客户端最终看到的 Tool 是以下四者的交集：

1. 公共 Manifest 声明的能力；
2. 当前 MCP 版本支持的能力；
3. 当前 Mod 实例握手公告的能力；
4. 当前权限策略允许的能力。

MCP 默认只公开 `game:read` 能力。需要执行游戏操作时，应由使用者显式启用写权限；权限不会因为取得一个 Ref 而自动扩大。

## 推荐调用方式

多数操作不是按名称或屏幕坐标直接执行，而是遵循“查询、取得 Ref、携带 Revision 操作、重新查询确认”的流程：

1. 使用 `query_runtime`、`query_world`、`query_inventory` 或 `query_ui` 取得当前事实；
2. 从查询结果中选择不透明 Ref，并原样回传；
3. 对 UI 或库存动作同时携带产生该 Ref 时的 Revision；
4. 操作完成后再次查询，确认游戏中的最终状态。

Ref 和 Revision 都属于当前 Mod 进程中的临时身份。菜单切换、对象变化、库存变化或游戏重启后，旧值可能返回 `STALE_REF`；调用方应重新查询，而不是解析 Ref 内容或猜测新坐标。

## 只读观察能力

只读能力需要 `game:read`，不会主动改变存档或游戏界面。

| 能力 | 读取内容 | 主要输入 | 主要结果与边界 |
|---|---|---|---|
| `query_runtime` | 日期、时间、天气、玩家位置、基础资源和 UI 摘要 | 无 | 返回运行时快照；尚未加载存档时返回 `NOT_READY`。 |
| `query_world` | 指定地图区域中的地块、对象、门、Warp、角色和动物 | 可选矩形或中心半径、实体类型过滤、集合开关和数量上限 | 默认查询玩家周围半径 8；单次最多覆盖 1024 个 Tile，实体与角色可以截断并明确标记。 |
| `query_inventory` | 玩家背包或已解析容器的槽位与物品 | 玩家背包选择器或容器 Ref，可选择是否返回空槽 | 返回完整库存快照、物品 Ref 和 `inventory_revision`；查询容器前通常先用 `query_world` 取得容器 Ref。 |
| `query_ui` | 当前菜单、`ui_revision`、可观察或可操作的 UI 元素 | 无 | 支持原版顶层菜单 Tab、普通对话、商店可见商品、箱子两侧槽位、背包与装备槽、制作配方；不支持的菜单只返回安全的公共外壳和 warning。 |
| `inspect` | 批量解析查询产生的不透明 Ref | 1 至 64 个 Ref | 每项独立返回已解析、过期、未找到、不支持或事实暂不可用；单项失败不会拖垮整批请求。 |

### `query_world` 当前事实覆盖

世界查询能为常见树木、作物、空的已耕地、资源、机器、容器、床、家具、掉落物、门、Warp、NPC 和农场动物提供类型化事实。空的 `HoeDirt` 会包含当前含水状态；带作物的耕地由作物事实表达含水状态。无法安全类型化的原版或第三方对象会尽量返回最小通用对象事实，而不是静默消失。

### `query_ui` 当前界面覆盖

- 原版 `GameMenu` 顶层页面：背包、技能、社交、地图、制作、收藏和设置；
- 原版普通对话：回答选项或单一“继续／结束”语义元素；
- 原版 `ShopMenu`：当前可见商品、物品事实、金币价格和有限库存；
- 受支持的原版 `ItemGrabMenu`：普通箱子、Big Chest 和内置冰箱的玩家侧与容器侧槽位；
- 原版背包页：当前菜单可见的玩家背包格，以及帽子、左右戒指、鞋、上衣、裤子和饰品槽；
- 原版非烹饪制作页：页面已经构建的配方、材料需求、可用数量、产出、已知状态和可制作状态。

查询只负责观察。商店商品、背包格、装备槽、箱子槽位和制作配方即使拥有 UI Ref，也不会被 `activate_ui` 当作通用坐标按钮点击；它们分别由专用写能力处理。

## 游戏操作能力

操作能力需要 `game:write`。其中标记为“会改存档”的能力可能消耗资源、改变物品、关系、金币或其他持久状态；Agent 应在调用前向使用者说明预期影响。

| 能力 | 用途 | 关键输入 | 成功结果 | 主要影响 |
|---|---|---|---|---|
| `say` | 在游戏聊天中发送文本 | `content` | 返回 Unicode 字符数量 | 对外通信 |
| `emote` | 播放受支持的玩家表情 | `emote` | 返回实际表情 | 对外表达 |
| `face` | 调整玩家朝向 | `direction` | 最终朝向及是否发生变化 | 不改存档 |
| `navigate` | 同地图或跨地图移动到位置或对象附近 | 位置或世界 Ref、到达方式、可选站位和到达后朝向 | 起点、终点、解析目的地、经过地图和执行统计 | 改变位置 |
| `interact` | 对相邻位置、对象或角色执行一次原生交互 | 位置或世界 Ref | 实际目标、能量变化和执行统计 | 可能改存档或关系 |
| `use_tool` | 对相邻目标使用当前工具 | 位置或世界 Ref、蓄力等级 | 实际目标、工具、蓄力、能量变化和执行统计 | 可能改存档并消耗能量 |
| `equip` | 切换当前背包工具栏选中物品 | 背包槽位或玩家物品 Ref，可选库存 Revision | 最终槽位、物品和是否变化 | 不负责穿戴装备槽 |
| `open_menu` | 打开受支持的顶层游戏菜单 | 菜单种类 | 菜单前后状态 | 不改存档 |
| `transfer_inventory_item` | 在已打开的受支持箱子菜单中转移指定数量物品 | 方向、物品 Ref、数量、UI Revision、玩家与容器 Inventory Revision | 实际转移数量、来源槽余量和双方新 Revision | 会改存档 |
| `set_equipment_slot` | 穿戴、替换或取下装备 | 装备槽 Ref、玩家物品 Ref或清空标记、UI 与 Inventory Revision | 最终装备槽、物品、新 Revision 和是否变化 | 会改存档 |
| `move_inventory_item` | 在背包页中整件移动物品或交换两个槽位 | 玩家物品 Ref、目标槽 Ref、UI 与 Inventory Revision | 起止槽位、是否变化、是否交换和新 Revision | 会改存档 |
| `craft_item` | 使用当前制作页配方执行有界批量制作 | 配方 Ref、制作轮数、UI Revision | 完成轮数、停止原因、产物、材料消耗及新 Revision | 消耗材料并改存档 |
| `purchase_shop_item` | 在当前商店中执行有界金币购买 | 商品 Ref、购买轮数、UI Revision | 实际物品、总价、购买前后金币、库存余量及新 Revision | 花费金币并改存档 |
| `activate_ui` | 激活 `query_ui` 明确允许的语义元素 | UI Element Ref、UI Revision | 被激活元素和菜单状态变化 | 影响取决于元素语义 |
| `close_menu` | 安全关闭当前菜单 | 无 | 菜单状态变化及是否本来已关闭 | 不改存档 |

## 关键能力边界

### 导航 `navigate`

导航支持同地图路径和跨地图路线编排，也可以导航到 `query_world` 返回的对象或角色 Ref 附近。跨地图时会处理已知 Warp、地图边界加载、可安全交互的门和玩家自建设施的唯一地图身份；目标对象在执行期间移动或消失时不会继续使用旧坐标。

导航超时不等于路径完全失败。超时错误会尽量包含总路线段数、已完成段数、最后确认位置和续跑提示，调用方可以从最后位置重新查询并继续执行。

### 交互与工具 `interact` / `use_tool`

两项能力都要求目标相邻，并在提交前重新验证目标身份与位置。`interact` 用于箱子、门、角色和其他原生交互；`use_tool` 使用当前装备的工具，并支持工具允许范围内的蓄力等级。它们调用游戏原生行为并检查后置状态，而不是只模拟一次输入后立即报告成功。

### 箱子转移 `transfer_inventory_item`

该能力只在 `query_ui` 已完整识别的受支持箱子菜单中工作。它使用明确的物品 Ref、转移方向、数量及双方 Revision，先规划堆叠与空槽，再原子提交；容量不足、Revision 变化或菜单状态不再匹配时不会偷偷缩减数量。

当前支持普通 Chest、Big Chest 和内置 Fridge。Global、Junimo、Mini Shipping、Separate Wallet、AutoLoader、Enricher、派生 Chest 及其他特殊 `ItemGrabMenu` 暂不开放写入。

### 背包与装备 `equip` / `set_equipment_slot` / `move_inventory_item`

`equip` 只负责选择玩家背包中的当前工具栏物品；穿戴帽子、戒指、鞋、衣服和饰品应使用 `set_equipment_slot`。整件物品在背包槽位之间移动或交换应使用 `move_inventory_item`，当前 V1 不提供拆分堆叠。

背包页动作以当前菜单实际可见且已解锁的槽位为写入范围，不会因为第三方扩展增加了底层背包容量而写入当前界面不可见的位置。

### 制作 `craft_item`

制作只能使用当前原版非烹饪 Crafting 页面由 `query_ui` 签发的配方 Ref。一次请求可以包含有限轮数：如果后续轮次材料不足或背包已满，结果会返回已完成轮数和明确停止原因，不会把已经制作的真实产物丢弃。

产物进入背包时复用与箱子转移相同的确定性堆叠、空槽提交和回滚机制。成功结果会汇总真实产物与材料消耗，并返回新的玩家库存和 UI Revision。

### 购买 `purchase_shop_item`

购买只能使用当前原版商店可见商品的 Sale Ref，并且当前 V1 只开放普通金币实物购买。一次请求全有或全无：金币、库存或背包容量不足时不会自动减少购买轮数；成功后实际商品必须完整进入背包，金币差额必须等于返回的总价。

非金币货币、额外交换物和其他特殊交易会保持只读展示或安全拒绝，不会被当作普通金币商品猜测执行。

### UI 操作 `activate_ui` / `close_menu`

`activate_ui` 只激活 `query_ui` 明确标记为可见且可用的元素，例如对话回答、普通对话的继续／结束语义和受支持菜单 Tab。库存、装备、制作和购买使用各自的专用能力，不通过屏幕坐标点击旁路校验。

`close_menu` 在没有菜单时幂等成功。普通对话只有在正文已经完整显示且确实位于安全末页时才会关闭；多页、问题、事件或强制 Modal 不会被粗暴退出。

## 超时、取消与失败

- `say`、`emote` 和五项查询能力为立即执行能力；其他操作走可观察的长任务状态机。
- 除 `say`、`emote` 和查询能力外，当前操作能力都可以在完成前请求取消。
- 每项能力都有 Manifest 声明的默认和最大超时；调用方可以在范围内覆盖，不能无限等待。
- `SUCCEEDED` 表示能力声明的后置条件已经被游戏侧观察确认，不只是输入已经发出。
- 失败后应根据错误码决定是否重新查询。`STALE_REF`、Revision 不匹配、UI 瞬态不完整或导航超时通常都需要先刷新事实，再决定续跑或重试。

## 当前公开集合的维护规则

新增、删除或调整能力时，必须先更新公共 Proto、Manifest 和行为契约，再更新 Mod Handler、MCP 支持面、生成 Schema、Fixture 与 Conformance 测试。本文只做同步说明；如果本文与 `spec/` 冲突，应以 `spec/` 为准并修正文档。
